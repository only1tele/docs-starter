---
title: Agent Wallets
subtitle: A wallet you issue to one of your customers. They fund it, and their agent spends from it within the limits you set.
---

The money is the customer's. You are the operator: you decide that a wallet exists, what it is called, and how much may leave it.

Each wallet has its own on-chain addresses, one covering Base and Tempo and one for Solana, so funding one wallet never touches another.

## A wallet exists only because you created one

Nothing else makes a wallet. Signing in does not, reading a balance does not, and opening a page does not. A customer with no wallet has no balance and no address, and that is a real state rather than a fault.

This is deliberate. A wallet costs real addresses to fund and splits a customer's money into pots. That is your decision, not an agent's.

## Creating one

```bash title="Create a wallet"
curl --request POST \
  --url https://api.mitu.ai/v1/customers/cus_ds9hazr8jd3l/wallets \
  --header "x-api-key: $MITU_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "name": "Travel",
    "limits": { "per_payment": 25, "monthly": 200, "approve_above": 50 }
  }'
```

```json title="Response"
{
  "id": "wal_fc2ff966abc04de09c22",
  "customer_id": "cus_ds9hazr8jd3l",
  "name": "Travel",
  "currency": "USDC",
  "limits": { "per_payment": 25, "monthly": 200,
              "approve_above": 50, "currency": "USD" },
  "addresses": [
    { "network": "base",   "address": "0xd7Ca1fdA..." },
    { "network": "tempo",  "address": "0xd7Ca1fdA..." },
    { "network": "solana", "address": "3c6SpTNK..." }
  ],
  "created_at": "2026-09-11T15:01:32.760Z"
}
```

You can also create one from the dashboard: **Wallets**, then **Create wallet**, then pick the customer, name it and set the limits.

## Names

The name is what the customer says out loud, because their agent names the wallet when paying: "pay from Travel". Choose names that read the way somebody would say them.

```text
Travel
Shopping
Office
```

Names are unique per customer, since two wallets called Travel would leave the agent guessing. Creating the same name twice returns the wallet you already have, so the call is safe to retry.

## Limits on creation

Limits you omit are inherited from the limits that customer already has. Omitted does not mean unlimited. [Limits and controls](/platform/agent-wallets/limits-and-controls) covers each control and the exact meaning of zero.

## Reading wallets back

```http
GET /v1/customers/{customer_id}/wallets
```

Returns every wallet the customer holds, with its limits.

## What the agent can do

An agent can list the wallets a customer holds, read a balance, read a funding address, and settle one of your charges from a wallet it is allowed to use. It cannot create a wallet, move money between wallets, withdraw, or change a limit. [Wallet tools](/platform/agent-wallets/wallet-tools) covers the tools an agent sees.

With one wallet an agent need not name it. With several it must, and naming none is refused with the names listed. An unrecognised name is refused too, rather than falling back to a default, because picking a pot on somebody's behalf is how money meant for travel buys office supplies.
