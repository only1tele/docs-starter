---
title: Issue your first wallet
subtitle: A pot your customer funds and their agent can spend from, within limits you set.
---

You need a customer. If you have not made one, [create your first customer](/guides/quick-start/create-your-first-customer) takes a minute.

<Note title="Not every business needs wallets">
Agent Wallets are for giving your own customers controlled spending power. If you only want agents to pay you, skip this and go to [accept your first payment](/guides/quick-start/accept-your-first-payment).
</Note>

<Steps>

<Step title="Create the wallet">

```bash title="Request"
curl --request POST \
  --url https://api.mitu.ai/v1/customers/cus_ds9hazr8jd3l/wallets \
  --header "x-api-key: $MITU_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "name": "Travel",
    "limits": { "per_payment": 250, "monthly": 2000, "approve_above": 150 }
  }'
```

```json title="201 Created"
{
  "id": "wal_fc2ff966abc04de09c22",
  "customer_id": "cus_ds9hazr8jd3l",
  "name": "Travel",
  "currency": "USDC",
  "limits": {
    "per_payment": 250,
    "monthly": 2000,
    "approve_above": 150,
    "currency": "USD"
  },
  "addresses": [
    { "network": "base",   "address": "0xd7Ca1fdA…" },
    { "network": "tempo",  "address": "0xd7Ca1fdA…" },
    { "network": "solana", "address": "3c6SpTNK…" }
  ],
  "created_at": "2026-09-11T15:01:32.760Z"
}
```

Name it for its purpose. The name is what the customer says out loud and what their agent passes, so `Travel` and `Office` work where `Wallet 1` does not. Names are unique per customer, and creating the same name again returns the wallet that already exists, which makes the call safe to retry.

</Step>

<Step title="Understand the limits">

All three are USD, while the balance is USDC. That is why the limits object names its own currency.

```text
monthly         the most this wallet may spend in a calendar month
per_payment     the intended ceiling for a single payment
approve_above   the intended threshold where the customer is asked
```

A limit you omit is inherited from the limits that customer already has. **Omitted does not mean unlimited**, and zero means no limit rather than a ceiling of zero.

<Warning title="Only the monthly limit currently gates a payment">
A payment that would take the wallet past `monthly` is held for the customer to approve rather than settling. `per_payment` and `approve_above` are stored and returned but are not yet read by the payment path, so do not present either to your customers as an enforced control.
</Warning>

</Step>

<Step title="Fund it">

The customer sends USDC to the wallet's address on a network it supports. Deposits are detected on chain and credited automatically.

<Warning title="Show the address with its network">
Base and Tempo share the EVM address. Solana's is different, and funds sent to the wrong chain are not recoverable. Present the pair, never a single bare address.
</Warning>

Only the create response carries the addresses. The wallet list returns names and limits without them.

</Step>

<Step title="Confirm it was credited">

`wallet.credited` fires when a deposit lands, carrying the amount, the network, the `tx_hash` and `balance_after` for that wallet alone.

```json
{
  "event": "wallet.credited",
  "event_data": {
    "wallet_id": "wal_fc2ff966abc04de09c22",
    "amount": "50.000000",
    "currency": "USDC",
    "network": "base",
    "balance_after": "50.000000"
  }
}
```

You can also read the customer's wallets back:

```bash
curl --request GET \
  --url https://api.mitu.ai/v1/customers/cus_ds9hazr8jd3l/wallets \
  --header "x-api-key: $MITU_API_KEY"
```

</Step>

<Step title="See what the agent gets">

Once the customer connects an AI client and Mitu knows who they are, four tools appear:

```text
list_wallets()                      the names they hold
get_balance({ wallet? })            a balance, or all of them
get_address({ wallet? })            where to fund one, labelled by chain
pay({ endpoint, method?, body?, wallet? })
```

The agent can read and it can pay. It cannot create a wallet, move money between wallets, withdraw, change a limit, or spend from a wallet it was not given.

With several wallets it must name one to pay from, and is refused with the names listed rather than allowed to guess.

</Step>

</Steps>
