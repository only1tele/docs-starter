---

Your application already has clients: web, iOS, Android, or another service. An agent is another one. The difference is that it reads a tool description instead of a screen.

So the work is not building an agent experience. It is describing the API you already have well enough that a model can choose correctly: what each operation does, when to reach for it, what it takes, and what it costs.

Mitu handles the layer in front of your API:

- MCP discovery and the tool list
- tool descriptions, schemas and pricing metadata
- customer authentication, by key or through your own OAuth
- payment challenges and settlement on paid operations
- signed forwarding to your backend

Your endpoints do not change, and they remain the source of truth for your business logic.

## What an agent sees

Register your endpoints once. Each becomes a named tool with its price attached. An agent that connects sees something like:

```text
get_menu              GET   /menu     free
create_order          POST  /orders   dynamic
check_delivery_zone   GET   /zones    free
call_endpoint         any path on your service
```

     Caption: "An agent's tool list for a merchant MCP, showing named endpoint

`call_endpoint` sits alongside the named tools and takes any path on your service. The named tools are what an agent should reach for, because they carry your description and your price, but they only cover paths you registered. A link pasted into a chat, or a sub-path beneath a registered one, has no tool of its own and would otherwise be uncallable. It is a fallback, not a substitute for defining tools properly.

## Connecting

```text
URL         https://mcp.yourdomain.com/mcp, or https://mcp.mitu.ai/mcp
Transport   Streamable HTTP
```

Customers authenticate either with a customer key you issue them or by signing in with your own identity provider. [MCP authentication](/platform/mcp/authentication) is the canonical description of both.

## Instructions

Free text sent to every agent that connects, before it sees any tool. Use it for what a tool description cannot carry: house rules, the order you expect calls in, and what you will not do.
