---
title: Sell your API to AI agents
subtitle: Turn the API you already run into paid capabilities that AI agents can discover, call and pay for.
---

Make your existing API available to AI agents and charge for the capabilities they use. You choose which operations agents can access and how much they cost, while Mitu handles the agent payment flow before a paid request reaches your API.

You do not need to build a separate API for agents or implement agent payment protocols yourself. Your existing API continues to provide the product, data or service you already operate.

<Note title="Agent Wallets are optional">
  You do not need to issue Agent Wallets to accept payments from AI agents. Agent Wallets are an optional way to give your own customers wallets that their AI agents can spend from.

  Learn more about [Agent Wallets](/platform/agent-wallets/overview).
</Note>

## Before you begin

You need a Mitu account, an existing API that Mitu can reach and at least one API operation that you want AI agents to pay to use.

You should also decide how you want to price the operation. Some capabilities have a fixed price for every request, while others need to calculate the amount based on the request.

<Steps toc={true}>
  <Step title="Connect your existing API">
    Start by connecting the API that already provides the capability you want to sell.

    In the dashboard, provide the base URL that Mitu should use when sending requests to your API.

    ```text
    https://api.example.com
    ```

    You do not need to create separate endpoints for AI agents. The same operations you already run can be made available through MCP.

    When you connect your API, Mitu provides a signing secret that your backend uses to verify requests sent by Mitu. Keep this secret secure and only use it from your server.

    Learn more about [Request verification](/platform/security/request-verification).
  </Step>

  <Step title="Choose what agents can pay for">
    Choose the API operations that you want AI agents to discover and use.

    For example, a company data API might make these capabilities available.

    ```text
    GET   /companies/search
    GET   /companies/{domain}
    POST  /reports
    ```

    Each operation becomes an MCP tool. Give each tool a clear name and description so an AI agent can understand what it does and when it should use it.

    ```yaml
    name: company_profile
    method: GET
    path: /companies/{domain}
    description: Retrieves a structured company profile for a specific domain
    when_to_use: Use when you need company information for a known website or email domain
    pricing_type: fixed
    price: 0.05
    ```

    If you already maintain an OpenAPI specification, you can import it instead of configuring each operation individually.

    Learn more about [MCP endpoints](/platform/mcp/endpoints).
  </Step>

  <Step title="Set the price">
    Configure how much an agent should pay to use the operation.

    Use fixed pricing when every successful request costs the same amount.

    ```yaml
    pricing_type: fixed
    price: 0.05
    ```

    Use dynamic pricing when the amount depends on the request. For example, the price of generating a report might depend on its size, the amount of data requested or another value calculated by your application.

    With dynamic pricing, your API determines the amount before the paid operation is completed. Mitu then handles the payment before sending the paid request back to your API.

    Other supported pricing models can be used for capabilities that need different charging behaviour.

    Learn more about [Pricing](/platform/payments/pricing).
  </Step>

  <Step title="Make the capability available to agents">
    Once the operation is configured, it becomes available as a tool through your MCP.

    Customers and other supported users can connect your MCP from compatible AI clients and discover the paid capabilities you have made available.

    For example, an agent connected to a company data service might discover tools such as:

    ```text
    search_companies
    company_profile
    company_report
    ```

    The tool descriptions and schemas tell the agent what each capability does, what information it requires and when it should be used.

    Learn more about [MCP tools](/platform/mcp/tool-schemas).
  </Step>

  <Step title="Let Mitu handle the payment">
    When an agent calls a paid operation, Mitu determines what the agent needs to pay before the operation can be completed.

    Mitu handles the supported agent payment flow, including payment requirements and supported protocols such as x402 and MPP. Your API does not need to implement these protocols separately.

    Once payment has been confirmed, Mitu sends the paid request to the API operation you configured.

    Your responsibility remains the same. Provide the product, data or service that the API operation represents.

    Learn more about [Agent payments](/platform/payments/agent-payments).
  </Step>

  <Step title="Verify the request from Mitu">
    Before your API processes the paid request, verify that it came from Mitu.

    Use the signing secret provided when you connected your API to validate the request signature. This allows your backend to confirm that the request and its payment information were sent through Mitu.

    Only fulfil the paid operation after verification succeeds.

    The dedicated verification guide covers the request headers, signature format and implementation examples.

    See [Request verification](/platform/security/request-verification).
  </Step>

  <Step title="Return your normal response">
    After the request has been verified, your API handles it using the same business logic it already uses.

    For example, an existing company profile endpoint might return:

    ```json
    {
      "name": "Example",
      "domain": "example.com",
      "industry": "Technology",
      "employees": 240
    }
    ```

    You do not need to create an agent-specific response format. Return the response your API normally provides for that operation.

    Mitu returns the result to the agent through the MCP request it started.
  </Step>

  <Step title="Track the payment">
    Payments made for your API capabilities are recorded in your Mitu account. Use payment events to keep your own systems updated when payments are completed or fail.

    For production integrations, configure webhooks rather than relying on the dashboard as your only source of payment state.

    Your payment records can be associated with the corresponding request so you can reconcile usage, payments and activity in your own systems.

    Learn more about [Webhooks](/platform/webhooks/overview) and [Events](/platform/webhooks/events).
  </Step>
</Steps>

## Your API is ready for agent payments

AI agents can now discover your paid capabilities, pay when required and receive the result from the API you already operate.

You continue to control what you sell, how much it costs and what your API returns. Mitu handles the agent-facing payment flow and sends verified paid requests to your backend.

Funds you receive are added to your Mitu balance and can be settled to a supported bank account or withdrawn to an onchain address.
